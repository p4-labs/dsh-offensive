# Updating dsh-offensive

The bundle vendors content from
[offensive-claude](https://github.com/hypnguyen1209/offensive-claude) and applies small
dsh-compatibility patches. All of it is regenerated by one script.

## Update flow

```bash
./scripts/sync-upstream.sh   # that's it
```

One command does everything: check upstream → regenerate content → bump patch
version → `npm pack` → `dsh plugin add` into the `web` profile (override with
`PROFILE=<name>`). **Restart dsh** afterwards to load the new bundle.

The script is a no-op when upstream hasn't moved, so it's safe to run on a
cron/launchd schedule for hands-off updates.

## How it works

- `upstream.lock` records the upstream commit the bundle content was generated from.
  The script compares it against `git ls-remote` and exits immediately when unchanged.
- On change, upstream is cloned shallow into a **temp dir that is removed after the
  run** — no upstream checkout is kept around.
- Everything under `modes/offensive/{skills,hooks,home,engine,templates,workflows,presets}`
  is **regenerated** on every sync. Do not hand-edit there; add patch steps to
  `scripts/sync-upstream.sh` instead.
- The dsh-compatibility patches the script applies:
  1. Hooks emit only the `hookSpecificOutput.additionalContext` JSON shape (the only
     one the dsh Claude Code hook bridge consumes) and announce the runtime framework root.
  2. SKILL.md frontmatter closing fences indented as `  ---` are normalized to `---`.
  3. `commands/engage.*.md` become flat skills `engage-*.md` (kebab-case names).
  4. `home/AGENTS.md` is generated from upstream `CLAUDE.md` with relative paths.

## Rolling back upstream

Check out the upstream commit you want in a temp clone and run the rsync/patch steps
manually, or edit `upstream.lock` to the old hash and re-run — the script will regenerate
from that commit when you point the clone at it.
